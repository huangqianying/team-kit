# 工程配置

> 本文件是**本工程专属信息的唯一位置**。团队基建内核（`AGENTS.md`、`docs/rules/团队协作契约.md`、`docs/rules/roles/`、`skills/` 下的内核 skill、`.githooks/`）在所有工程逐字相同，凡写「见工程配置「<节名>」」处，都以本文件对应一节为准。
> 由 team-kit 安装时生成模板，此后由本工程维护，kit 同步不会覆盖它。节名是内核引用的锚点，**不要改名或删节**；不适用的写「无」。

## 产品

- **产品名**：观澜 · Vista（全称：工作台账管理系统）；工程代号 DeptTracker
- **命名分层**：对外 / 产品 / 界面 / 文档一律用「观澜 Vista」；仓库、目录、包名等工程内部标识沿用 DeptTracker，不做全局替换。
- **一句话定位**：面向组织 / 部门的台账管理系统 ——「人人工作台，向上汇聚成管理者视图」：每个成员管理自己的全部工作，向上汇聚为管理者全局视图。
- **版本真值源**：`system-version.json`（`{version, status, updated}`；`status` 取 `in-progress` / `released`）。版本号为孵化期 `v0.0.x`。
- **注意**：产品里的「台账」是业务对象，团队状态账本（`.team-ledger/`）是协作工具，两者无关。

## 目录

| 用途 | 位置 |
|---|---|
| 后端 | `server/`（Java 21 · Spring Boot · PostgreSQL，Maven 多模块：`app` `kernel` `store` `session` `audit` `contract` `codegen` `architecture` `testkit`） |
| 产品前端 | `web/`（Vue 3 ＋ TypeScript ＋ Vite） |
| Web UI 原型 | `prototypes/<版本>/`（pnpm workspace，见「命令」） |
| 研发自测试（SE） | 后端 `server/*/src/test/`；前端 `web/test/`（unit / browser / conformance） |
| QA 独立测试 | `qa/`：执行器 `qa/driver/`、候选构建 `qa/bin/`、harness `qa/harness/`、证据 `qa/evidence/<候选>-<轮次>/`；不依赖 `web/`、`server/` 的测试代码 |
| 数据库迁移 | `server/store/src/main/resources/db/migration/`（Flyway） |

## 命令

> 以仓库根为工作目录；被测命令须是命令串最后一个进程，保证退出码真实。Java 一律用 `JAVA_HOME=$(/usr/libexec/java_home -v 21)`。

| 用途 | 命令 |
|---|---|
| 后端构建 | `(cd server && ./mvnw -B -q -DskipTests clean package)` |
| 后端研发自测 | `(cd server && ./mvnw -B verify)` |
| 前端类型检查 / 构建 | `pnpm -C web typecheck` · `pnpm -C web build` |
| 前端研发自测 | `pnpm -C web test:unit` · `pnpm -C web test:conformance` · `pnpm -C web test:browser` |
| QA 测试 | 按本轮测试方案的执行器入口，如 `QA_WORK=<目录> QA_PORT_BASE=<端口> node qa/driver/<轮次>/run.mjs --execute --candidate <SHA> --out <证据目录>` |
| 原型启动 | `pnpm -C prototypes dev` → `http://127.0.0.1:5173/`，各版本在 `/v<版本号>/` |
| 原型自检 | `pnpm -C prototypes/<版本> typecheck` · `build` · `test` |

**并行测试的隔离参数**：见 `qa/README.md`「并行执行」（端口起点 `QA_PORT_BASE` 至少相差 50、独立 `QA_WORK`、独立 `--out`、负载敏感组串行）。

## 分支与发布

- **分支策略**：日常在 `develop` 上推进，不另建特性分支或 worktree；版本放行后 `develop` 以 `--no-ff` 合入 `main` 并打附注 tag `v<版本号>`。
- **合入与推送**：产品负责人明确放行后由 SA 合入、推送；推送只在产品负责人要求或授权时进行。主树保持在 `develop`，合入 `main` 可用 `git commit-tree develop^{tree} -p main -p develop` ＋ `update-ref`，不切分支。

## 部署

- **部署 skill**：`skills/deploy/`（凭据加载、连通性自检、quick / full 两种模式、回退）
- **环境**：测试机 `192.168.209.84`（应用经 nginx 发布 `8090`）；生产机 `192.168.207.84`。两台与 aiTokenReport 共用，目录与端口须与其错开，不动它的容器与目录。凭据在 `.deploy/credentials.ini`（不入库，600）。
- **部署后验证**：部署 skill 里的健康检查与冒烟；必要时真实浏览器冒烟。
- **默认约定**：部署必须显式指定环境，不设默认。
