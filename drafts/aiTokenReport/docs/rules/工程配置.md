# 工程配置

> 本文件是**本工程专属信息的唯一位置**。团队基建内核（`AGENTS.md`、`docs/rules/团队协作契约.md`、`docs/rules/roles/`、`skills/` 下的内核 skill、`.githooks/`）在所有工程逐字相同，凡写「见工程配置「<节名>」」处，都以本文件对应一节为准。
> 由 team-kit 安装时生成模板，此后由本工程维护，kit 同步不会覆盖它。节名是内核引用的锚点，**不要改名或删节**；不适用的写「无」。

## 产品

- **产品名**：睿析 · Prism（中文名「睿析」，英文代号 `Prism`）；仓库工程名 `aiTokenReport` 沿用不变。
- **一句话定位**：AI API 用量追踪报表系统，从 AI 代理服务器（sub2api）拉取用量数据，按组织 / 个人 / 模型 / 供应商 / 日期多维度分解，提供管理员、系统业务员、普通用户报表。
- **版本真值源**：`system-version.json`（`{version, status, updated}`；`status` 取 `in-progress` / `released`）。版本号为 `v2.0.x`。

## 目录

| 用途 | 位置 |
|---|---|
| 后端 | `backend/app/`（FastAPI ＋ SQLAlchemy（SQLite）＋ APScheduler；业务路由以 `/report/` 为前缀） |
| 产品前端 | `frontend/src/`（Vue 3 ＋ TypeScript ＋ Element Plus ＋ Vite）；不要编辑 `frontend/dist/`、`frontend/node_modules/` |
| Web UI 原型 | `prototypes/<版本>/`（根 `prototypes/` 管版本入口与共享 npm 依赖；不进部署包） |
| 研发自测试（SE） | 后端 `backend/tests/dev/`；前端与源码同目录 `frontend/src/**/*.test.ts` |
| QA 独立测试 | 后端 `backend/tests/qa/`（建议 `test_qa_` 前缀，用 `from backend.tests...` 绝对导入）；前端 `frontend/tests/qa/**/*.test.ts`；部署后 E2E `backend/tests/qa/e2e/`（`e2e-test.py`，刻意不用 `test_` 前缀、不进 pytest 收集）。共享夹具 `backend/tests/conftest.py` |
| 数据库迁移 | `database/migrations/` |

## 命令

> 以仓库根为工作目录；被测命令须是命令串最后一个进程，保证退出码真实。

| 用途 | 命令 |
|---|---|
| 后端初始化 / 本地运行 | `cd backend && python init_db.py` · `cd backend && uvicorn app.main:app --reload` |
| 后端测试 | 全量 `.venv/bin/python -m pytest backend/tests -q`；仅 QA `… backend/tests/qa -q`；仅研发自测 `… backend/tests/dev -q` |
| 前端开发 / 测试 / 构建 | `cd frontend && npm install && npm run dev` · `cd frontend && npm test` · `cd frontend && npm run build` |
| 全量测试 | 依次跑后端测试、前端测试、前端构建 |
| Docker | `docker compose up -d --build` |
| 原型启动 | `npm --prefix prototypes run dev -- --host 0.0.0.0 --port 5280 --strictPort` → `http://localhost:5280/` |
| 原型自检 | `npm --prefix prototypes run typecheck` · `npm --prefix prototypes run build` · `npm --prefix prototypes test`（可给 Vitest 传 `<版本>/src/...spec.ts` 定向） |

**并行测试的隔离参数**：暂无专门的并行执行器；需要分路时，由 SA 在派活单里指定各路使用的数据库文件、端口与输出目录。

## 分支与发布

- **分支策略**：后续开发统一在 `develop` 分支进行，SA 与各角色均不再按特性、BUG 或角色另建分支 / 工作树。`main` 为发布集成分支，产品负责人确认合入后由 SA 将 `develop` 以 `--no-ff` 合入 `main`，完成后回到 `develop` 继续工作。除非产品负责人另有明确指令，不在 `main` 直接开发。
- **合入与推送**：产品负责人确认后由 SA 合入、推送。

## 部署

- **部署 skill**：`skills/deploy-aitokenreport/`
- **环境**：测试服 `DEPLOY_ENV=test skills/deploy-aitokenreport/scripts/deploy.sh`；生产服 `DEPLOY_ENV=production skills/deploy-aitokenreport/scripts/deploy.sh`。部署凭据存 `.deploy/credentials.ini`（按环境分节，不入库，600），首次照 `.deploy/credentials.ini.example` 填；本地凭据从 `backend/.env.example` 复制。
- **部署后验证**：`skills/e2e-test/`（打真实部署环境）；涉及登录、权限、路由、部署配置或生产入口路径时必须考虑 E2E，是否执行按项目规则询问。
- **默认约定**：用户明确要求「部署 / 部署到服务器」时默认部署到测试服；只有明确要求生产部署时才部署生产。部署视为成熟流程，直接执行部署脚本，无需额外人工确认；生产部署须人工确认。

**SE / QA / UI 动手前必读的项目规范**：
- PM：系统设计规范（判需求可行性时对照）。
- SE：系统设计规范、错误码响应规范（接口与错误处理必须遵守）。
- QA：系统设计规范、错误码响应规范（权限、隔离、错误码是测试设计的输入）；部署核证时读 `skills/e2e-test/`、`skills/deploy-aitokenreport/`。
- UI：错误码响应规范中与界面提示相关的部分。

**页面与组件命名约定**：`Readonly*View.vue` 为业务员只读页，`Personal*View.vue` 为普通用户页，`*MaintenanceView.vue` 为管理员页。
