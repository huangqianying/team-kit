# 观澜 Vista 团队协作状态账本设计

> 定位：本文是契约 `docs/rules/团队协作契约.md`「附：状态账本」的具体形态与落地设计，工具是 `skills/team-ledger/team-ledger.py`（用法见同目录 `SKILL.md`，本文不复述命令）。**这是开发团队的协作管理抓手，与观澜 Vista 产品自身的业务台账数据是两回事，勿混淆。**
>
> 2026-10-15 按产品负责人决定「砍到三条」重写。历史版本见 git：CCB 运行时（`.ccb/`、消息流自动唤醒）已于 2026-09-22 卸载；本次又砍掉核锚、归档、渲染三族（理由见 §一）。

## 一、射程：原依据已撤，新依据只支撑一小块

账本的立项依据是 **CCB 时代的异步协作**：四个角色是互相看不见的独立会话，账本是**唯一的派活通道** —— 我写一条，对方下次开工读到，才知道该干什么。

现在 PM/UI/SE/QA 是当前 Claude Code 或 Codex 会话的 **subagent**：任务由 SA 直接派出，可能同步返回，也可能需要等待异步结果。结论由父会话收齐，**账本不负责唤醒或派活**；它不是 CCB 时代的跨会话消息总线。

需要持久化的依据是 **SA 的上下文会被压缩，或因额度耗尽而串行切换平台**。压缩 / 换端之后「停在哪、谁欠谁一棒、哪件事在等人裁」不能依赖旧会话的记忆或子任务标识；账本和已提交产物共同支持接班。

所以结论不是「依据撤了就删」，而是**按真依据重裁射程**。裁出来恰好三条：

| 命令 | 答的问题 | 为什么别处答不了 |
|---|---|---|
| `append` | 把状态写进唯一的事实源 | — |
| `stale`（`--hours 0` 即当前态） | 谁停太久 / 现在全局停在哪 | 可从 `docs/reviews/` 派生，但要逐份读；账本一行就给 |
| `owner` | 哪些事卡在产品负责人手上 | 别处没有这个队列 |

### 砍掉了什么，为什么

| 砍掉 | 理由 |
|---|---|
| `verify-artifact` / `verify-candidate`，及 `--artifact` / `--at` / `--candidate` / `artifact_sha` / `review_sha` / `candidate_sha` | 产物版本及证据由契约 §三、§五统一规定；账本只记录状态与索引，不另设核锚字段和命令 |
| `show` / `render` / `.team-ledger/ledger.md` | md 是 jsonl 的**派生态**，却被人读、被文档引用 ⇒ 同一事实两个源。当前态改由 `stale --hours 0` 现算现打 |
| `owed` | 判据与 `stale` 完全重合（非终态行即待派的棒），并进 `stale`，每行带出接续方 |
| `items`（粒度自查） | 粒度判据仍在契约 §附；靠评审记录计数挑不出语义重复，实测真重复项相似度 0.49、合法异项 0.90 |
| `archive` / `set-version` / `log` | 归档的前提是有历史，而历史已于 2026-10-15 被产品负责人清空。版本改为**只读** `system-version.json` |
| `MERGED_ROLES` / `--close-merged` | 它为 `ta`/`ui` 的遗留非终态行而存在，那些行随历史一并消失 |

规模：**2019 行 → 687 行**（工具 390 ＋ 判据 297）。

## 二、形态：只有事件流

| 层 | 文件 | 性质 | 说明 |
|---|---|---|---|
| **事实源** | `.team-ledger/ledger.jsonl` | 追加式事件流（运行时，gitignore） | 每次状态变更**追加一行 JSON**（`O_APPEND`，行 < PIPE_BUF 原子），并由 `.team-ledger/ledger.lock` 的 `flock` 互斥 |
| **当前态** | 无文件 | 现算 | 每个 `(role, item)` 取**最新事件** = 当前态，由 `stale --hours 0` 打印。**不再落第二份文件** |
| **版本真值源** | `system-version.json`（仓库根） | **入 git** | `append` 据此给事件打 `version` tag；读不到则落 `_infra` 并告警。本工具**只读不写** |
| **工具** | `skills/team-ledger/team-ledger.py` + `SKILL.md` | 入 git | 原子追加 + schema 强校验 + 两条巡检。`.claude/skills` 与 `.codex/skills` 软链至此 |
| **判据** | `skills/team-ledger/test_team_ledger.py` | 入 git | 67 条，`python3 skills/team-ledger/test_team_ledger.py`，全程隔离到临时目录 |

**为什么事件流当事实源**：直接让多 agent 就地改一张 markdown 表是读-改-写竞态（会串写 / 覆盖）。改成「只追加、当前态派生」后，写路径退化为单行原子追加，并发安全且零协调；当前态是纯函数派生，随时可重算，且免费带来完整历史。

**账本落唯一主工作树**：`.team-ledger/` 是 gitignore 的工作区目录，每棵 git worktree 各一份。工具按 git common-dir 解析主工作树根来定位账本，任一 worktree 调用都写同一本账、读同一版本，杜绝每棵 worktree 各持一本账的分叉。脚本自身路径用 `realpath` 解析（`.claude/skills` 是指向 `skills/` 的软链，两条调用路径必须算出同一个仓库根）。

## 三、事件 schema

一行 JSON，字段：

| 字段 | 必填 | 取值 |
|---|---|---|
| `ts` | 自动 | 落账时间（东八区） |
| `version` | 自动 | 取自 `system-version.json`；`--version` 可显式覆盖；读不到为 `_infra` |
| `role` | 是 | 枚举：`pm` / `ui` / `sa` / `se` / `qa` |
| `item` | 是 | 工作项短标识；同一工作项跨状态**保持同名**。大小写 / 空格 / 连字符 / 全角差异视为同事异名、硬拒并提示既有原名；确属另起一项加 `--force-new-item` 并在 `--note` 写明理由 |
| `phase` | 否 | 枚举（标注链路环节）：`requirement` / `design` / `ui-design` / `spec` / `plan` / `dev` / `ui-review` / `test-design` / `test-case` / `test` / `accept` / `review` / `deploy`（中文门名自动归一） |
| `status` | 是 | 枚举：`进行中` / `待评审` / `评审中` / `阻塞` / `完成` / `交接`。终态 = `完成` / `交接` |
| `to` | 条件 | 接续方角色；`status=交接` / `待评审` 时**必填** |
| `blocker_role` | 条件 | 被卡方角色；`status=阻塞` 时**必填**。等产品负责人裁定写 `owner`，进待裁决清单 |
| `blocker` | 条件 | 卡在什么；`status=阻塞` 时**必填** |
| `round` | 否 | 评审轮次。**计数口径按「同一 ledger item 的同一门」累计，上限 3 为硬约束**（契约 §五「最大轮次」）—— 这条使 `item` 的同名硬拒从洁癖变成承重 |
| `decision` | 否 | 枚举：`APPROVED` / `CR` |
| `review` | 否 | 正式评审记录路径 `docs/reviews/<版本>/…` |
| `forced_new_item` | 自动 | 用了 `--force-new-item` 即留痕，可 grep 审计 |
| `note` | 否 | 一句话说明。**判定不要塞进 note**，用 `decision` 字段才统计得到 |

枚举字段一律**强校验**，非法值直接退出**且不落账** —— 校验不通过还落账等于让账本进脏数据。

## 四、协作协议

**落账（全员，每次状态变更即记）**：开工 `进行中`、求评审 `待评审`（必带 `--to`）、评审 `评审中`（带 `--round`）、遇阻 `阻塞`（必带 `--blocker` 与 `--blocker-role`）、通过 `完成`、下派 `交接`（必带 `--to`）。**非终态必须指定接续方** —— 但它只是给 SA 看的状态标记，**落账不唤醒任何人**；棒由 SA 读账本后主动派出，角色不得绕过 SA 自行调度（契约 §三）。

**SA 每回合两步**（契约 §四）：

1. `stale [--hours N]` —— 谁停太久（默认 24h；**退出码 0 才是「确无停滞」**，`ts` 脏到判不了退 2 —— 判不了 ≠ 全清）
2. `owner` —— 哪些事卡在产品负责人手上、只能等人（退出码 1 = 有待裁决）

当前态看 `stale --hours 0`：列出全部非终态项，每行带接续方（`→ SE` / `→ OWNER（等人裁决，不派 subagent）`）、卡点与轮次。

## 五、生命周期

- 账本是**团队级、跨会话长存**的（不随单次开发会话重置）。
- `完成` 的工作项不进 `stale`、不进 `owner`，自然沉默，无需归档动作。
- 不再有归档命令。历史全在 `.team-ledger/ledger.jsonl` 里只增不减；真要瘦身是人工的事，且**瘦身即丢历史**，须经产品负责人（2026-10-15 清空即一次这样的决定）。

## 六、边界

- 账本记录的是**开发团队的协作状态**，不是观澜 Vista 产品的业务台账数据（后者由产品自身的后端与业务表承载）。二者独立 —— 产品做的是「工作台账」，本账本记的是「谁在做这个产品、做到哪一步」。
- 账本不替代评审记录（`docs/reviews/<版本>/`）与验收报告；它是**状态索引**，指向而不复制那些产物。**DoD 仍是 `APPROVED` + 评审记录落盘**。
- 两类工作分账：产品开发带产品版本号；工程基建带 `--version _infra`（`AGENTS.md` §二）。
- **不在射程内的别往回加**。`test_team_ledger.py` 里有两组反向判据，钉住被砍的 9 个子命令与 4 个落锚参数必须报错 —— 要加回来，先改那两条判据。
