# 规范按需阅读索引设计（借鉴 HelixHarness「往后」第 14 条）

> 状态：已批准（产品负责人，2026-11-24）。
> 日期：2026-11-24
> 规模：中等（完整设计，交付前经实施者审读；审读意见已并入，标「维护方判断」的是据此定的）

## 为什么

代理开工前要读的规范越来越长，最大的是内核 `docs/rules/UI设计规范.md`：1,776 行、约 117 KB、25 节。SE 的角色文件写着「涉及前端时必读」，快速链路写着「改到界面按 `UI设计规范.md` 自查」，于是改一个表格的列宽也要通读全文。读得多不等于读得准：上下文被占满后，真正相关的那几条反而容易被忽略。

HelixHarness 的做法是给规范建索引，每行写「文件 · 定位 · 加载时机」，代理按当前任务逐行判断，只读命中的。负责人选了方案 B：

- 工程配置「项目规范」表加「何时读」一列；
- 再给 UI 设计规范加一份分节索引；
- 分节索引放在规范开头（放法 1）。

## 目标、不做、反目标

**目标**：
1. UI 设计规范开头有一节「按需阅读」：每次都读的节，加上按任务再读的节。SE 编码（含快速链路改界面）、SA 评审涉及界面的产物、PM 写涉及界面的需求时按它读。
2. 工程配置「项目规范」表有「何时读」一列，PM、SE、QA 按它对照本次任务读工程自己的项目规范。

**不做**：
- 不改 UI 设计规范的任何规则内容和节号（包括不给 §22 补节号）；
- 不改「要与规范逐条对」场合的读法，这些场合仍通读全文（见下）；
- 不改 UI 角色「依据恰两份」：UI 不读项目规范，项目规范里要 UI 遵守的内容由 PM 写进需求作为 AC；
- 不替工程改它们的工程配置（只处理内核，工程侧记入交接说明 §5.2）；
- 不做 HelixHarness 的时间戳缓存、「已加载」声明。

**反目标**：
- 照搬 HelixHarness「未进索引的文件一律不读」，索引漏写一节，代理就漏读规则。本设计的口径是**索引给出最少要读的范围，拿不准就读全文**；
- 索引与正文节号对不上，或某一节的正文哪一行都读不到。

## 方案

| 方案 | 做法 | 取舍 |
|---|---|---|
| A | 只给工程配置「项目规范」表加「何时读」 | 两个工程要手改；对 vista 几乎无收益，对 prism 只是换个格式 |
| **B（选定）** | A，再给 UI 设计规范加分节索引 | 分节索引全在内核里，同步即生效；真正省下阅读量的是这一部分 |

分节索引放在哪：

| 放法 | 取舍 |
|---|---|
| **1. UI 设计规范开头加一节（选定）** | 索引和正文在一个文件里，改节号时一眼看到；kit 测试核两者一致 |
| 2. 单独一份内核文件 | 正文不动，但两份文件会对不上，内核多一个文件 |
| 3. 写进 SE、PM 的角色文件 | 映射表分散、重复维护 |

## 设计

### 1. UI 设计规范「按需阅读」一节

位置：文件头的引言块之后、`## 0. 设计哲学` 之前，节名 `## 按需阅读`（不编号，正文节号全部不变）。内容：

**通读全文的场合**（都要「与规范逐条对」，或者涉及面太广）：
- UI 角色出原型；
- PM 审原型、审 SE 实现的界面（规范符合性逐条对）；
- 新增页面（维护方判断：§22 检查清单有 6 条不带节号，靠它路由会漏读；新增页面本来就是大活）；
- 拿不准该读哪些节时。

**其余场合**：先读「每次都读」，再读本次任务命中的行，取并集；表里没有的任务读全文。

**本工程实例**（`docs/rules/UI设计规范-本工程实例.md`）**每次整份读**（维护方判断）：它只记本产品的取值和例外，两个工程最长约 200 行；按节号对应会漏掉挂在别的节号下的例外登记（如 vista 挂在 §2.7 下的表格选中行例外）和不编号的「待对齐」清单。

**每次都读**（201 行，约占全文一成）：

| 节 | 为什么每次都读 |
|---|---|
| §0 设计哲学 | 规则冲突时的裁决顺序 |
| §1 令牌体系总览 | 不得硬编码、暗色为一等公民 |
| §2.4 语义化令牌 | 组件只引用这一层 |
| §4 间距、栅格与断点（整节） | 间距令牌几乎每个界面任务都用；§4.1 断点全站统一、强制（维护方判断：原稿只列 §4.1，§4 正文的间距令牌哪一行都读不到） |
| §20 数据展示格式化 | 两条红线管所有展示数据和文案的地方 |
| §21 无障碍与降级 | 聚焦、对比度、命中区，任何可交互元素都适用 |
| §22 新增页面检查清单 | 改完逐条自查用 |

**按任务再读**：

| 本次任务涉及 | 再读 |
|---|---|
| 表格、列表页 | §11.2、§12、§13、§17、§18 |
| 筛选栏、查询条件 | §12、§15.1、§15.2 |
| 表单、输入 | §14、§15、§18.3 |
| 弹窗、抽屉 | §16、§15、§18.3 |
| 按钮、操作列 | §14、§13.3 |
| 卡片、汇总信息卡、仪表盘、指标卡、图表 | §11、§5、§2.5、§6.5 |
| 页面骨架、顶栏、侧栏、导航、页签 | §7、§8、§9、§10、§23.2 |
| 登录页 | §7 |
| 组织树、双栏、看板、大屏、投屏 | §10 |
| 颜色、主题、对比度、新的文字与底色组合 | §2 |
| 字体、字号、数字排版 | §3 |
| 圆角、阴影、材质、玻璃 | §5 |
| 动效、过渡 | §6 |
| 空状态、加载、加载失败 | §18 |
| 消息提示、通知中心 | §19、§23 |
| 移动端、窄屏 | §23、§16 |
| 一次性凭据 | §15、§16 |
| 富文本编辑器 | §24 |

写法约定：`§N` 表示整节（含全部子节），`§N.M` 只读该子节。**每个一级节都至少在一处被整节引用**（维护方判断：只引子节的话，该节正文没有子节标题的部分谁都读不到）。上表的覆盖情况：§0、§1、§4、§20、§21、§22 在「每次都读」；§2、§3、§5–§19、§23、§24 都在「按任务再读」里整节出现。

### 2. 工程配置「项目规范」加「何时读」

`profile/docs/rules/工程配置.md` 的「项目规范」表由两列改为三列：

| 规范 | 位置 | 何时读 |
|---|---|---|
| UI 设计规范 · 通用规则（内核） | `docs/rules/UI设计规范.md` | 涉及界面时：按它开头「按需阅读」读 |
| UI 设计规范 · 本工程实例 | `docs/rules/UI设计规范-本工程实例.md` | 读通用规则时整份读 |
| 前端技术栈与组件库、产品前端主题、原型主题 | 原样 | 涉及前端时 |
| 其他项目规范 | <例：系统设计规范> | <例：涉及权限/鉴权/数据隔离时；`必读` 表示开工前都读，可限定角色，如「SE、QA 必读」> |

- 「何时读」写成「涉及 X / Y 时」；每次都读的写「必读」，可限定角色。
- 原来表下的「**SE / QA / UI 动手前必读的项目规范**」一段**并进这一列**，模板里删掉该段。
- 「页面与组件命名约定」一段不动。

**未改的工程照常工作**：表里没有「何时读」列时，`kit check` 只警告（同「并行线」软节的做法），各角色仍按原来的「动手前必读」那段读。

### 3. 读法写进哪里

| 文件 | 改什么 |
|---|---|
| `docs/rules/roles/se.md` 第 4 条 | 「涉及前端时必读」→ 涉及前端时按 UI 设计规范开头「按需阅读」读；新增页面通读；本工程实例整份读 |
| `docs/rules/roles/se.md` 快速链路一条（「改到界面按 `UI设计规范.md` 自查」） | 改为按「按需阅读」读后自查 |

| `docs/rules/roles/pm.md` 第 2 条 | 同上 |

| `skills/diff-impact/SKILL.md`「二、方法」第 1 步 | 「与改动相关的规范」后补「（按「何时读」一列判断；UI 设计规范按其开头「按需阅读」）」 |

`sa-review`、`technical-review` 不单独改：SA 评审读规范的口径随 AGENTS.md。

### 4. 检查

- **kit 测试（核内核自身）**：
  - UI 设计规范有 `## 按需阅读`，且位于 `## 0.` 之前；该节里不出现 `### ` 开头的行（现有测试 `t_demo_breakpoints_match_spec` 用 `spec.index("### 4.1")` 取第一次出现处）；
  - 索引里引用的每个节号（`§N`、`§N.M`、`§N.M.K`）在正文都有对应标题，**按编号匹配，不按标题级别**（§16.1、§11.2.1 是 `####`，§11.7.1 是 `###`）；
  - 正文每个一级节（§0–§24）都在索引里**整节**出现至少一次；
  - se.md、pm.md、qa.md 引用「按需阅读」或「何时读」；pm.md 写明审原型和审界面通读；se.md 和契约里不再有「按 `docs/rules/UI设计规范.md` 自查」；
  - 工程配置模板「项目规范」表头含「何时读」，且不再有「动手前必读的项目规范」一段。
- **`kit check`（核工程）**：工程配置「项目规范」表头没有「何时读」时警告「项目规范表缺「何时读」列（未加时各角色按原必读段读）」，不报错。

### 5. 对工程

- 同步后 UI 设计规范的分节索引立即生效，工程不用改什么。
- 「何时读」列要各工程自己加，`kit check` 会一直警告到加上为止。记入交接说明 §5.2：
  - vista：只有 UI 设计规范两行，照模板填即可；
  - prism：原来按角色写的必读段条件各不相同（PM 判需求可行性对照系统设计规范、SE 接口与错误处理、QA 部署核证读 `skills/e2e-test/`、`skills/deploy-prism/`），要逐条改写成「涉及 X 时」，两个 skill 不在表里，要补行或另写；给 UI 列的「错误码规范中与界面提示相关的部分」与内核「UI 依据恰两份」冲突，应改由 PM 写进需求。
