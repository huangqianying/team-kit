# 规范按需阅读索引设计（借鉴 HelixHarness「往后」第 14 条）

> 状态：草案，待产品负责人审阅。
> 日期：2026-11-24
> 规模：中等（完整设计，交付前经实施者审读）

## 为什么

代理开工前要读的规范越来越长，最大的是内核 `docs/rules/UI设计规范.md`：1,776 行、约 117 KB、25 节。SE、PM 的角色文件写着「涉及前端时必读」「涉及界面时必读」，于是改一个表格的列宽也要通读全文。读得多不等于读得准：上下文被占满后，真正相关的那几条反而容易被忽略。

HelixHarness 的做法是给规范建索引，每行写「文件 · 定位 · 加载时机」，代理按当前任务逐行判断，只读命中的。负责人选了方案 B：

- 工程配置「项目规范」表加「何时读」一列；
- 再给 UI 设计规范加一份分节索引；
- 分节索引放在规范开头（放法 1）。

## 目标、不做、反目标

**目标**：
1. UI 设计规范开头有一节「按需阅读」：每次都读的节，加上按任务再读的节。SE 编码、快速链路改界面、SA 评审、PM 判可行性时按它读。
2. 工程配置「项目规范」表有「何时读」一列，各角色按它对照本次任务读工程自己的项目规范。

**不做**：
- 不改 UI 设计规范的任何规则内容和节号；
- 不改 UI 角色出原型、PM 审原型的读法，这两处仍通读全文，因为要「与规范逐条对」；
- 不替工程改它们的工程配置（只处理内核，工程侧记入交接说明 §5.2）；
- 不做 HelixHarness 的时间戳缓存、「已加载」声明。

**反目标**：
- 照搬 HelixHarness「未进索引的文件一律不读」，索引漏写一节，代理就漏读规则。本设计的口径是**索引给出最少要读的范围，拿不准就读全文**；
- 索引与正文节号对不上，读到的是错的节。

## 方案

| 方案 | 做法 | 取舍 |
|---|---|---|
| A | 只给工程配置「项目规范」表加「何时读」 | 两个工程要手改；对 vista 几乎无收益，对 prism 只是换个格式 |
| **B（选定）** | A，再给 UI 设计规范加分节索引 | 分节索引全在内核里，同步即生效；真正省下阅读量的是这一部分 |

分节索引放在哪：

| 放法 | 取舍 |
|---|---|
| **1. UI 设计规范开头加一节（选定）** | 索引和正文在一个文件里，改节号时一眼看到；kit 测试核两者一致 |
| 2. 单独一份内核文件 | 正文不动，但两份文件会对不上，内核多一个文件 |
| 3. 写进 SE、PM 的角色文件 | 映射表分散、重复维护 |

## 设计

### 1. UI 设计规范「按需阅读」一节

位置：文件头的引言块之后、`## 0. 设计哲学` 之前，节名 `## 按需阅读`（不编号，正文节号全部不变）。内容：

**谁通读全文**：
- UI 角色出原型；
- PM 审原型（需求符合性 ＋ 规范符合性逐条对）；
- 拿不准该读哪些节时。

其余场合按下面读：先读「每次都读」，再读本次任务命中的行。**工程里的 `UI设计规范-本工程实例.md` 按同一节号对应**：读了哪一节，实例里同号的节（含「例外登记」）一并读。

### 2. 工程配置「项目规范」加「何时读」

`profile/docs/rules/工程配置.md` 的「项目规范」表由两列改为三列：

| 规范 | 位置 | 何时读 |
|---|---|---|
| UI 设计规范 · 通用规则（内核） | `docs/rules/UI设计规范.md` | 涉及界面时：按它开头「按需阅读」读 |
| UI 设计规范 · 本工程实例 | `docs/rules/UI设计规范-本工程实例.md` | 与通用规则同号的节一并读 |
| 前端技术栈与组件库、产品前端主题、原型主题 | 原样 | 涉及前端时 |
| 其他项目规范 | <例：系统设计规范> | <例：涉及权限/鉴权/数据隔离时；`必读` 表示开工前都读> |

- 「何时读」写成「涉及 X / Y 时」，关键词用顿号或斜杠分隔；需要每次都读的写「必读」，可限定角色，如「SE、QA 必读」。
- 原来表下的「**SE / QA / UI 动手前必读的项目规范**」一段**并进这一列**，模板里删掉该段。
- 「页面与组件命名约定」一段不动。

**未改的工程照常工作**：表里没有「何时读」列时，`kit check` 只警告（同「并行线」软节的做法），各角色仍按原来的「动手前必读」那段读。

### 3. 读法写进哪里

| 文件 | 改什么 |
|---|---|
| `docs/rules/roles/se.md` 第 4 条 | 「涉及前端时必读」→ 涉及前端时按 UI 设计规范开头「按需阅读」读：每次都读的节 ＋ 本次任务命中的节，本工程实例同号节一并读；拿不准读全文 |
| `docs/rules/roles/se.md` 第 2 条 | 「项目规范」里列给 SE 的必读文件 → 按「项目规范」表的「何时读」对照本次任务读；表里还没有这一列时，按原来的必读段读 |
| `docs/rules/roles/pm.md` 第 2、4 条 | 同上；第 4 条另写明：**审原型时通读全文** |
| `docs/rules/roles/qa.md` 第 2 条 | 同 se.md 第 2 条 |
| `docs/rules/roles/ui.md` | 不改：出原型通读全文 |
| `AGENTS.md`「UI 设计规范」一段 | 加一句：按需阅读见规范开头，出原型、审原型通读 |
| `AGENTS.md`「本工程另有的项目规范…及各角色必读范围」 | 改为「…及何时读，见工程配置「项目规范」」 |

`sa-review`、`technical-review` 不单独改：SA 评审读规范的口径随 AGENTS.md。

### 4. 检查

- **kit 测试（核内核自身）**：
  - UI 设计规范有 `## 按需阅读`，且位于 `## 0.` 之前；
  - 索引里引用的每个节号（`§N`、`§N.M`、`§N.M.K`，含区间两端）都在正文有对应标题；
  - 正文每个一级节（§0–§24）都出现在「每次都读」或「按任务再读」里（新加一节忘了进索引会失败）；
  - se.md、pm.md、qa.md 引用「按需阅读」或「何时读」；pm.md 写明审原型通读；
  - 工程配置模板「项目规范」表头含「何时读」，且不再有「动手前必读的项目规范」一段。
- **`kit check`（核工程）**：工程配置「项目规范」表头没有「何时读」时警告「项目规范表缺「何时读」列（未加时各角色按原必读段读）」，不报错。

### 5. 对工程

- 同步后 UI 设计规范的分节索引立即生效，工程不用改什么。
- 「何时读」列要各工程自己加，`kit check` 会一直警告到加上为止。prism 括号里已写了各规范管什么，改起来就是搬一列；vista 只有 UI 设计规范两行。记入交接说明 §5.2。
